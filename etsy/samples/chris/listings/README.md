# Chris sample products: Etsy listings

Ten listings, one folder each (`p01_golf_marker` … `p10_mini_figure`). Every folder holds exactly five 2000×2000 JPEGs in Etsy upload order, plus `listing.txt`.

| # | file | what it is |
|---|---|---|
| 1 | `01_hero.jpg` | lifestyle hero render (Blender Cycles, product in context); this is the Etsy thumbnail |
| 2 | `02_*.jpg` | product-only render of the real print mesh, 3/4 (or high 3/4 for flat items) |
| 3 | `03_*.jpg` | product-only, front or top |
| 4 | `04_*.jpg` | product-only, side or a second angle |
| 5 | `05_spec.jpg` | spec and personalisation card: name, GBP price, size, material, fit, personalisation |

The suffix on 02–04 is the camera (`34`, `high34`, `front`, `side`, `top`, `under`).

`listing.txt` contains TITLE (≤140 chars), PRICE (GBP), DESCRIPTION, TAGS (13, each ≤20 chars), MATERIALS and PROCESSING, ready to paste into Etsy. `listings.json` has the same data for all ten in machine-readable form, generated by `listings.py`.

## Rebuild
- Views: `VSAMP=36 ./views.sh r0N_<product>.py [views]` (scripts/; one Blender job at a time)
- Hero: `HRES=1400 HSAMP=48 blender -b --python r0N_<product>.py`
- Compose: `python3 compose.py [pid ...]`. The `SEL` dict picks which views go in slots 02–04 for each product.
