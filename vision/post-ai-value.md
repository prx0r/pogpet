# What is valuable after AI makes software cheap (founder research, verbatim 2026-10-10)

> Software cost collapsing ≠ solved. Reliability, desirability,
> distinctiveness and commercial success still cost. Roadmap driver:
> OddHobb turns AI designs into verified purchasable physical products;
> Pogtown turns disposable AI content into persistent characters with
> audiences, reputations, commercial value. Own neither models, engines,
> nor agent frameworks.

## Commoditised vs valuable

| Layer | Happening | Response |
|---|---|---|
| Code generation | automated | use coding agents, don't compete |
| 3D assets | commoditising | integrate Meshy + providers |
| Rigging/animation | easier, imperfect | runtimes + narrow gap repair |
| Game creation | Google/Unity entering | don't build a general creator |
| Voice agents | mature blocks | LiveKit + providers |
| Character memory/tools | OSS emerging | keep Pogtown identity + history |
| Multiplayer | solved | integrate when needed |
| Electronics comms | ESPHome/Muse SDKs | adapters, not protocols |
| Physical design validation | fragmented | INVEST |
| Multi-supplier manufacturing | hard to coordinate | INVEST |
| Taste/entertainment quality | needs audience feedback | INVEST |
| Distribution/trust | hard to automate | INVEST |
| Fulfilment | physical ops problem | INVEST |

Regenerable (mesh, code, voices) vs accumulating (preference history,
recurring characters, validated recipes, supplier reliability). Invest in
the accumulators.

## Build vs buy (checked Oct 2026)

Use/watch, don't compete: Google Playground, Unity Spark (closed beta),
Meshy (integrate now), Marble (selective rooms), Mixamo (check licence),
LiveKit (integrate now), Nakama (when needed), Muse Gadget SDK (optional
adapter), ESPHome (first hardware), JLC API (priority), InteractiveHtmlBom

readiness (Meshy rig vs Freaktown rig, Marble mesh vs manufacturing mesh,

  entertaining format → Funnier comparisons → audience feedback.

  histories → Funnier distributes + evaluates → OddHobb converts demand
  into gifts/products. No fourth character DB, no new avatar engine.

## Value hierarchy (cheapest up)

Generation → Selection/taste → Verification/execution → Distribution/
relationships → Accumulated proprietary history. Bottom three are ours.
Funnier ("do people like this?") + compiler ("can we make and sell it?")
beat generic generation or standalone POD.

## Manufacture what becomes popular

Developer creates (Muse gadget/game/character/sensor/DIY) → OddHobb
detects demand (stars + "where to buy", orders, Funnier votes, enquiries;
200 stars + 40 buy-requests beats 10k passive stars) → manufacturing
pathway (permission → CAD/BOM → quote → prototype → QA) → sell + fulfil
(creator attributed + paid, OddHobb produces). Data Gardens becomes the
opportunity radar; score on partnership interest, prebuilt demand,
template compatibility, margins, assembly complexity, IP permission.

## Pog portability contract (don't freeze)

Compact persistent identity (id, creator, name/premise/voice, model/rig
refs, performances/relationships/achievements, product + device ids).
Same Pog in generated game, Funnier set, cottage speaker, figurine —
engines change, identity/ownership/permissions/history persist.

## Six months: two flywheels

Entertainment (Pog → set → votes → champion → following → merch) +
manufacturing (demand → AI design → verify → quote → produce → fulfil →
learn). Characters drive product demand; products deepen character
experience. Asset = reliability at finding what's wanted, owning

from creative software to creative economies. Weekly watch on Spark,
